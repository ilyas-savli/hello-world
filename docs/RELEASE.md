# Releasing

Generated by `render_ci.py` from `docs/SPEC.md` → "Distribution & CI/CD". Change the channels there and
re-run the script (`--apply-gradle --prune`); don't edit the managed workflows by hand.

| Channel | When | What happens | Needs |
|---|---|---|---|
| Local APK | on request | `tools/export_build.sh --type apk --out ~/Desktop/builds/hello-world` builds, signs, verifies and copies the files there | a local upload keystore (or `--debug-sign`) |
| Firebase App Distribution | push to main, or by hand | stage release build, signed with the upload key, to the `testers` group | `FIREBASE_SERVICE_ACCOUNT_JSON`, `KEYSTORE_*`, `firebase.stage.appId` in gradle.properties |
| Signed AAB artifact | `v*` tag, or by hand | prod AAB kept as a CI artifact | `KEYSTORE_*` |

**Version codes (CI-07):** CI builds use `tools/ci/version.sh` — `app.versionCode` + commits × 10 + 0 (test
build) or 1 (release); the version name is the tag (`v1.2.3` → `1.2.3`). Local builds use gradle.properties.

**Release:** `git tag v1.2.3 && git push origin v1.2.3`.
