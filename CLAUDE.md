# Hello World — instructions for Claude

This project was generated by the **android-engineer** skill and must keep following its coding rules.

## Before you change code
1. Read the rule files that apply to the change in `~/.claude/skills/android-engineer/references/rules/`
   (always `core.md`; then e.g. `compose.md`, `designsystem.md`, `i18n.md`, `testing.md`, `architecture.md`).
   If the skill isn't installed, the same rules are summarised below.
2. Look at an existing feature (e.g. `feature/hello`) and follow the same structure.
3. Small changes, bug fixes and tickets: use the skill's Task mode (`/android-engineer`, `references/modes/task.md`).

## Non-negotiables (summary)
- Modules: `feature/*` → `core/*` only; features never depend on each other.
- Architecture: **MVVM** (`docs/SPEC.md` "Architecture:", ARCH-00). UI (MVVM): `XRoute` (gets the ViewModel) + stateless `XScreen` (state in, events out). A screen with no state of its own (like `HelloScreen`) needs no Route or ViewModel. One `StateFlow<XUiState>` per ViewModel (`architecture.md` ARCH-02/03, `reference-feature.md`).
- Components: generic look in `core/designsystem/components` (no strings), shared app components in `core/ui`,
  feature-only UI in the feature. Features never use raw Material 3 Button/FAB/TopAppBar/Card/TextField.
- Strings: only in `core/i18n/src/main/res/values*/strings_<feature>.xml`, keys prefixed `<feature>_`, every language.
  Shared texts in `strings_common.xml`. Access via `import com.ilyassavli.helloworld.core.i18n.R`.
- No hard-coded colors/dp — `HelloWorldTheme.spacing`, `MaterialTheme.colorScheme/typography`.
- No `!!`, no `GlobalScope`, no hard-coded Dispatchers (add an `@IoDispatcher` qualifier in `core/common` with the first repository and inject it), no `Log`/`println`, no TODOs.
- Files ≤ 300 lines. Every ViewModel/repository/mapper has unit tests; every screen a Compose UI test.
- No lint baseline, no `@Suppress` without `// justified: <reason>`.
- Tablet (if `material3-adaptive` is in the version catalog): layouts by window size class, never by device type;
  screen tests at three sizes (`adaptive-layout.md`).
- Android TV (if `app-tv/` exists): TV screens live in `tv/feature/<name>` and reuse that feature's ViewModel; only
  `core/designsystem-tv` components (no `clickable`, no phone Material 3); every TV screen has a focus map in
  `docs/SPEC.md` and a focus-map test; remote keys only in `app-tv/…/input/`; run `python3 tools/check_tv.py all .`
  (`tv-focus.md`, `tv-input.md`, `tv-ui.md`, `tv-platform.md`).
